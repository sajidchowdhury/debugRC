# Glossary — RC_ERP_v2 Terms

> **Module:** Reference
> **Audience:** All (engineers, AI assistants, accountants, new contributors)
> **Status:** Canonical
> **Last reviewed:** Initial creation (Phase 0)
> **Source of truth:** This file, compiled from code, config, and existing `docs/`

This glossary defines the business and technical terms used throughout `AI_CONTEXT/`. Terms
are grouped: **Accounting**, **Inventory**, **Sales/Purchasing**, **Business/Org**, and
**Technical**. Each entry is kept short; deeper detail lives in the relevant module doc.

---

## Accounting terms

| Term | Definition |
|---|---|
| **CoA** | Chart of Accounts. The list of ledgers (accounts) used by the ERP. Seeded by migration `2025_01_05_000001_seed_default_chart_of_accounts.php`. See `accounting/chart-of-accounts.md` (Phase 6). |
| **GL** | General Ledger. The central ledger of double-entry bookkeeping. Implemented as `journal_entries` + `journal_lines` (partitioned). |
| **Journal Entry** | A single balanced accounting entry (Dr = Cr). One `journal_entries` row + N `journal_lines` rows. Enforced balanced by DB trigger `enforce_balanced_journal_entry()`. |
| **Journal Line** | One leg of a journal entry (a single Dr or Cr on a ledger). |
| **Dr / Cr** | Debit / Credit. Every journal entry MUST have total Dr = total Cr. |
| **Ledger** | An account in the CoA (`ledgers` table). Has a `ledger_nature` tag that tells the posting engine how to use it. |
| **Ledger Nature** | A behavior tag on a ledger (e.g. `cash_bank`, `ar`, `ap`, `inventory`, `sales_revenue`, `cogs`, `retained_earnings`). 7 are "critical" (each must resolve to exactly one active ledger); the rest are "extended". See `docs/migration/journal_posting_rules.md` §2. |
| **AR** | Accounts Receivable. Asset. Money customers owe us. Ledger nature `ar`, normal balance Debit. |
| **AP** | Accounts Payable. Liability. Money we owe suppliers. Ledger nature `ap`, normal balance Credit. |
| **COGS** | Cost of Goods Sold. Expense. The cost of inventory sold. Ledger nature `cogs`, normal balance Debit. Posted on sales challan issue / sales return confirm. |
| **Sub-ledger** | A detail ledger backing a GL control account (AR per customer, AP per supplier, employee payable, bank). Reconciled to the GL control account. See `accounting/subledger-reconciliation.md` (Phase 6). |
| **Control Account** | The GL ledger that a sub-ledger rolls up to (e.g. the single `ar` ledger is the control account for all customer sub-ledger rows). |
| **Reversal** | The act of undoing a posted journal/stock transaction by creating a **new** entry with swapped Dr/Cr. Originals are NEVER mutated. See `accounting/reversal-vs-cancellation.md` (Phase 6). |
| **Cancellation** | Marking a draft/unposted transaction as cancelled. Different from reversal (which applies to posted transactions). |
| **Posting** | The act of creating journal lines for a business event (e.g. finalizing an invoice posts revenue + AR + COGS). ~40 posting methods exist. |
| **Accounting Period** | A time window (usually a month) that can be open or closed. Posting to a closed period is blocked (config-overridable for admin). |
| **Fiscal Year** | The financial year. Has periods. Year-end close moves net income to retained earnings. See `accounting/fiscal-year-period-close.md` (Phase 6). |
| **Period Close** | Closing an accounting period to prevent further postings. Logged in `period_close_logs`. |
| **Running Balance** | A maintained cumulative balance on sub-ledgers/ledgers, reconciled against recomputed sums. See `accounting/running-balance.md` (Phase 6). |
| **Reconciliation** | Comparing the sub-ledger total to the GL control account balance; differences below `gl_reconciliation_tolerance` (default ৳0.02) are treated as balanced. |
| **GL Reconciliation Tolerance** | Max acceptable Dr-Cr drift. Config `accounting.gl_reconciliation_tolerance` = 0.02 Taka. |
| **Manual Journal** | A journal entered directly by an accountant (not generated by a transaction). Role-restricted. |
| **Money Transfer** | Moving cash between cash/bank ledgers. Posts Dr to destination, Cr to source. |
| **Retained Earnings** | Equity ledger nature `retained_earnings`. Target of year-end close. |
| **Taka (৳)** | The Bangladeshi currency (BDT). The system's money unit. APP_TIMEZONE is `Asia/Dhaka`. |

## Inventory terms

| Term | Definition |
|---|---|
| **Moving-Average Cost** | The inventory costing method used. Each receipt recalculates the weighted-average unit cost; issues consume at that cost. Re-derived from first principles in `docs/migration/avg_cost_rule.md`. See `inventory/stock-costing.md` (Phase 8). |
| **Stock Ledger** | The append-only ledger of every stock movement: `stock_transactions`. Each row has a `reference_type` (receive/issue/adjust/transfer/damage/sales/sales-return/etc.) and `reference_id`. Reversible, never deleted. |
| **Warehouse Stock** | Per-warehouse on-hand quantity + avg cost. Materialized/summarized in `warehouse_stock` (and partitioned daily summary MVs). |
| **Stock Take** | A physical count session. Freezes outbound movements for the warehouse(s) being counted, computes variances, posts gains/losses on approval. State machine: draft → counting → submitted → approved → posted (→ reversed/re-opened). See `inventory/stock-take.md` (Phase 8). |
| **Freeze (Outbound)** | During a stock take, outbound stock movements for the counted warehouse are blocked. Throws `WarehouseFrozenForCountException` (rendered globally as 422). |
| **Stock Adjustment** | A manual increase or decrease of stock (with reason + approval). Posts inventory + shrinkage/surplus. See `inventory/stock-adjustment.md` (Phase 8). |
| **Damage** | A write-off of damaged inventory. Has witness/accountable parties, an approval workflow, and posts to `damage_loss` (falls back to `inventory_shrinkage`). See `inventory/damage.md` (Phase 8). |
| **Warehouse Transfer** | Moving stock between warehouses. Inner-branch (same branch) or cross-branch (intercompany: posts Due-to / Due-from Branch). See `inventory/warehouse-transfer.md` (Phase 8). |
| **UoM** | Unit of Measure. Products can have multiple UoMs with conversion factors (`product_uom_conversions`). `UomConversionService` converts quantities. |
| **ABC Classification** | Inventory items ranked by value (A = high value, C = low). Drives cycle-count frequency. See `inventory/stock-take.md` (Phase 8). |
| **Variance** | The difference between counted qty and system qty in a stock take. Positive = surplus, negative = shrinkage. |
| **Reversal (Stock)** | A stock_transaction with reversed flag/`reversal_of` reference that negates a prior movement. The stock ledger is append-only. |

## Sales / Purchasing terms

| Term | Definition |
|---|---|
| **Sales Invoice** | The customer-facing billing document. Created from a cart, finalized to post revenue + AR (+ transport + discount) and (via challan) COGS. |
| **Sales Challan** | The godown/dispatch document. Issuing a challan dispatches goods and posts COGS + inventory reduction. An invoice references one or more challans. |
| **Godown** | Warehouse / stock room. "Prepare godown" = generate the dispatch/challan for picking. |
| **Sales Cart (Draft)** | A draft sales invoice (`sales_draft_carts`) held per user+branch. Auto-cancelled by a scheduled job if stale. Concurrency-controlled. |
| **Sales Return** | A customer returning goods. Confirmed returns restock inventory and post a reversal (revenue reversal + AR reduction + inventory + COGS reversal). Guarded against double-return by `SalesReturnableQty`. |
| **Commission** | Salesperson commission. Rule-based (`commission_rules`, targets, product-group targeting). Calculated by `CommissionService`. |
| **Transport Cost** | A charge on a sales invoice for transport. Posts to `transport_revenue` (income) or passes through as expense. |
| **Purchase Order (PO)** | A document ordering goods from a supplier. States: draft/approved/cancelled. |
| **Purchase Receive (GRN)** | Goods Received Note. Receiving goods against a PO. Posts inventory + AP. |
| **Purchase Return** | Returning goods to a supplier. Posts reversal of the receive. |
| **Customer Payment** | A receipt from a customer (cash/cheque/bank). Allocates to one or more invoices. Reduces AR. |
| **Supplier Payment** | A payment to a supplier. Reduces AP. |
| **Employee Transaction** | An advance or salary/payment to an employee. Posts `employee_payable` + cash/bank. |
| **Branch Demand** | An inter-branch requisition (one branch demands stock from another/the HO). Has repricing, intercompany settlement via money transfer / customer payment. See `finance/branch-demand.md` (Phase 13). |
| **Call a Day** | A field on sales invoices (`call_a_day`) used for daily salesperson activity tracking. |

## Business / Organizational terms

| Term | Definition |
|---|---|
| **Remote Center** | The business operating this ERP. A multi-branch distribution/retail company in Bangladesh. |
| **BDIX** | Bangladesh Internet Exchange. The production VPS is to be provisioned on a BDIX-connected host (Phase 1, pending). |
| **Branch** | An operating location. Each branch is RLS-isolated. A `branches` row. |
| **Warehouse (Godown)** | A stock location belonging to a branch. A `warehouses` row. |
| **HO** | Head Office branch (default branch code `HO`). |
| **Intercompany** | Transactions between two branches of the same company. Posts Due-to-Branch (liability) and Due-from-Branch (asset) ledger pairs. Ledger natures `interbranch_payable` / `interbranch_receivable`. |
| **Consolidation** | Combining multi-branch financials into a company-wide view. `ConsolidationService` + `consolidation_runs`. |
| **Cost Center / Dimension** | Analytical tags on postings for management reporting. `dimensions` + `dimension_values`. |
| **Investigation Mode** | A system policy state (`SystemPolicy`) that puts the ERP into a restricted/compliance mode. Managed via `SystemPolicyService` + Gate. |
| **Shadow Mode** | A mode where a new implementation runs alongside the old one and results are compared without affecting production data. Used for warehouse transfers and branch demand. |

## Technical terms

| Term | Definition |
|---|---|
| **RLS** | Row-Level Security. PostgreSQL feature enforcing that a session only sees rows matching its `app.branch_id` GUC. Set per request by `SetAppBranchId` / `SetApiBranchContext` middleware. |
| **GUC** | PostgreSQL Grand Unified Configuration variable. Here, `app.branch_id` is a custom GUC set per request to drive RLS. |
| **MV (Materialized View)** | A pre-computed view stored on disk, refreshed periodically. 7 MVs exist for reporting; refreshed by `php artisan refresh:report-views`. |
| **CTE** | Common Table Expression (SQL `WITH` clause). Used for complex reports. |
| **pg_partman** | PostgreSQL extension for automated partition management. Used for time-series partitioning of large tables (journal lines, stock transactions, audit logs). |
| **Partitioning** | Splitting large tables by time (e.g. monthly) for performance + archival. Applied to `journal_entries`, `journal_lines`, audit logs, sub-ledgers, transaction headers. |
| **Listen/Notify** | PostgreSQL pub/sub. The app LISTENs on channels; DB triggers NOTIFY on data changes. `ListenNotifyService` fans out to SSE/notifications. |
| **SSE** | Server-Sent Events. `SseController` streams realtime events to the browser. |
| **Sanctum** | Laravel's token auth package. Used for the REST API (`users.api_token`, SHA-256 hashed). |
| **Credential Version** | A counter on `users` bumped on password/role change. `CheckCredentialVersion` middleware invalidates sessions whose version is stale. |
| **Anti-Corruption Layer (ACL)** | A boundary that isolates the legacy MySQL archive from the Laravel domain. DTOs + Repository + Service in `app/Archive/`. |
| **Service Layer** | The pattern: controllers are thin; all business logic lives in `app/Services/*`. Never bypass services. |
| **Form Request** | A Laravel request class that validates input. Lives in `app/Http/Requests/`. |
| **Policy** | A Laravel class authorizing actions on a model. 8 exist (SalesInvoice, CustomerPayment, SupplierPayment, EmployeeTransaction, ManualJournal, StockAdjustment, Damage, SystemPolicy). Defense-in-depth behind role middleware. |
| **Gate** | Laravel authorization facade. Defines `manage-system-policy`, `view-notification-rules`, and model policies. |
| **Audit Trait** | `AuditableMasterData` trait logs master-data changes to audit tables. |
| **Branch Scope** | An Eloquent global scope (`app/Models/Scopes/BranchScope.php`) auto-filtering queries by branch. |
| **Document Sequence** | A counter-based document numbering service (`DocumentSequenceService`) using advisory locks (not `SELECT FOR UPDATE`). |
| **Advisory Lock** | PostgreSQL `pg_advisory_lock`. Used for document sequencing to avoid lock contention. |
| **pgloader** | The ETL tool used to bulk-load legacy MySQL data into PostgreSQL. Config in `database/etl/pgloader.load`. |
| **Blade** | Laravel's templating engine. 326 views in `resources/views/`. UI reproduces legacy Bootstrap markup. |
| **Pint / Larastan** | Code formatter (Pint) and static analyzer (Larastan) used in dev. |
| **Pail** | Laravel log tailing package (dev). |
| **Debugbar** | Dev-only debug toolbar (`barryvdh/laravel-debugbar`). |
